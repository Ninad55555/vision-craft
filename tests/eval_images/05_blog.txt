pen Fieldnotes Engineering Design Changelog Subscribe Engineering Why we rewrote our parser (and you should too) Maya Okafor - Oct 12, 2025 - 8 min read Our old parser had one job: turn configuration files into a tree. It did that job for four years, and it did it wrong for three of them. Last quarter we rewrote it in 1,100 lines and cut config errors by 71%. The best code is the code you delete. The second best is the code you finally understand well enough to rewrite. The problem with lenient parsing Lenient parsing feels friendly. It silently drops unknown keys, guesses types, and returns something "close enough". But every silent recovery is a bug you will debug at 2 a.m. six months later. config = parse(text) # never raises # ... 400 lines later ... assert config is not None # it was None What we changed We made every error explicit, attached line numbers to all of them, and added a did-you-mean suggestion for unknown keys. The parser is smaller, slower by 4%, and dramatically more honest. Maya Okafor Staff engineer, infrastructure
